# Reel product specification

Last verified: 2026-11-07 (native addition; Continue 2026-10-28; other web sections 2026-10-16)
Repository/branch: Reel / feat/reel-native-android; web baseline from main
Verified against: current working tree
Purpose: Intended product behavior, with emphasis on the recommendation experience.

## Product behavior

Native 1.0.2 presents title details with one poster beside facts (stacked at large font sizes), horizontal swipeable cast circles with full names, and a responsive library poster grid with the existing search/status/collection controls and private progress. Actor taps open dedicated provider-qualified profiles, preserving known portrait/name and the originating public work even when optional credits fail. Real source portraits are preferred; unavailable photos use an honest silhouette. Profiles show available birth/country/profession facts and source links; credits are explicitly incomplete rather than invented.


The Android client adds native Discover / Ask Reel / Search / Library / You tabs, onboarding, existing-account sign-in/registration/recovery, poster and person details, watchlists/saved picks, private notes/ratings/collection tags, dated movie/episode actions, activity date editing, calendar, viewing statistics, local dark/light/system appearance and optional haptics. Lumi is an original contextual character. The website and existing user data remain authoritative and compatible.

Native 1.0.1 broadens movie search with a second public IMDb source and shows results independently of slow catalog responses. Posters retry alternate URLs and recover by exact provider identity; a title is not hidden when artwork is unavailable. The visible Back control and Android Back share a policy: return through existing screen/tab history, otherwise go to Discover; allow the OS exit action only at Home with no history. Predictive-back opt-in is disabled for compatibility; physical-device confirmation remains tracked in the mobile verification report.

Ask combines existing guided questions, accumulated intent, real catalog retrieval and the authenticated recommendation API. Clarification is bounded, shown picks are excluded, regeneration is supported, and fallback is labeled catalog matching. Conversation history exists only within the open app session. Rating-based affinity is opt-in and needs at least three ratings of 8–10. Search separates titles and people, preserves saved state during deduplication, and stores account-scoped recent queries locally.

Native statistics use dated viewing events and exclude undated baseline progress/reading. The initial release calendar uses available TVMaze episode dates; missing Kitsu-only guides and unknown dates stay explicit. Reading entries remain visible but native chapter/page actions are outside this movie/TV client. Google provider, push delivery, account deletion, service availability and server chat persistence are not invented. Device verification and APK evidence are tracked in `docs/mobile-verification.md`.

The library's Continue shelf includes every `going` title across media types. Drag handles support mouse and touch reordering; arrow keys, Home/End, and explicit earlier/later buttons in View all provide non-drag alternatives. A manually chosen order is stored in `ui.continueOrder` through the existing guest/account preference persistence, without changing title timestamps, watch/read progress, or History. Unordered new titles remain visible after manually ordered titles; removed/inactive IDs are ignored. The View all button opens a centered native dialog with a blurred backdrop, a searchable full list, cover art, current position, resume time, basic metadata, notes preview, and existing progress/Finish actions. Clickable titles open full Details without a separate Details button. Compact cards distinguish a larger current season/episode from smaller completed/all episode counts, without the trailing word “watched.” Counts derive from the released episode guide and checked/baseline progress, not from the episode cursor alone; continuous anime show absolute episode numbers without calendar-year seasons. Reading positions and totals use page/chapter units. The dialog expands to 1360px by 860px within the viewport, with compact chrome, a shared action/reorder footer, two columns on desktop and one on mobile, and the same saved order as the shelf. Closing restores focus; opening Details closes the popup first. Account changes close the popup and render only the new account's list. Reordering cancels on Escape, pointer cancellation, window blur, or a refresh/account change. Keyboard announcements, pointer handles that do not hijack normal scrolling, light/dark themes, reduced motion, and English/French/Arabic copy are supported. Home's separate next-episode preview is unchanged.

Long-running anime One Piece (1999), Naruto (2002), and Naruto Shippuden (2007) use a single absolute-episode input and an Arcs & episodes explorer with named ranges. Provider broadcast years are never presented as seasons. Other anime with calendar-year guides also use continuous episode numbers, with an honest generic guide when no curated arc mapping exists. Jujutsu Kaisen, My Hero Academia, and ordinary season-based anime retain season controls. Entering an episode commits an undated baseline through that episode, updates the checkboxes, and removes higher checked flags on corrections. Individual checkbox edits, next episode, and Finished synchronize the displayed input and explorer; Finished checks every released episode only. Saved dated History is not fabricated or erased by numeric baseline edits. Signed-in edits update the owner-scoped private `user_titles` row, verify a row was returned, and roll back on failure. Existing provider episode keys are retained, including pre-existing single-sequence Kitsu keys during metadata refresh. Arc labels/ranges are curated from linked official/distributor guides; ongoing ranges extend with released provider episodes, and standalone/unmapped episodes stay accessible as Additional episodes.

Library and online details restore a shared cover-over-banner header: the portrait cover overlaps the bottom-left of the landscape banner, with the title beneath the banner beside the cover. Responsive overlap and cover sizes preserve this arrangement on mobile. Banner candidates are the custom History banner, title/year-matched curated landscape art, and saved provider banner. If none loads, lazy artwork discovery requests exact-ID TVMaze original backgrounds, Kitsu original cover images, or Cinemeta backgrounds through an exact IMDb ID (direct or Wikidata P345). Missing identities use unique exact title/year matches, never arbitrary remakes. Actual loaded images must be at least 1280px wide and 360px tall with landscape ratio >=1.3; genuine panoramic banners such as 1500×500 are accepted. Banners retain native proportions without cropping, blur, dimming, artificial upscaling, or poster substitution and can open with keyboard or pointer in the full-image viewer. An honest unavailable state remains when providers supply no qualifying art. Discovery has a bounded 15-minute in-memory cache, rejects detached/account-stale responses, saves only native-validated public artwork and attribution, and does not change catalog identity or personal progress.

Item details offer a Reset progress action with a themed, viewport-centered confirmation popup and a dimmed, blurred backdrop, not a browser alert. The custom-styled HTML dialog makes the background inert, contains keyboard focus, and scrolls internally on short screens. It previews the Want status, zeroed progress, and cleared resume point/dates, with an explicit preservation note. Keep progress receives initial focus; Cancel, Escape, or a backdrop click restores the trigger without closing Details. Submission disables duplicate actions and dismissal, announces saving, and leaves a retryable inline error on failure. It returns the item to Want, clears episode/chapter/page progress, watched-episode flags, resume time, and start/completion dates, while preserving History, rating, notes, favorites, artwork, and title facts. Episodic tracking returns to season 1, episode 0. Signed-in resets use the existing owner-scoped library sync and roll back on save failure.

Reel is one personal queue across media types, preserving medium-specific progress and making the next useful action quick. A user can work entirely locally, optionally sign in to sync a private library, search public catalogs, inspect details, and decide what to watch or read.

## Personal tracking destinations

Home's Upcoming releases and Calendar cover the entire library, irrespective of status, with a shared toggle limiting releases to In progress (`going`), Finished (`done`), and Caught up (`waiting`). Home shows the next confirmed date per distinct title over the next 365 days, in batches of eight titles, with expandable remaining dates. A separate Date not announced section retains provider-confirmed undated seasons and year/month release windows. Ongoing manga/manhwa without dated chapter records have an explicit unavailable-schedule disclosure, not a fabricated next chapter. TVMaze supplies episodes and season announcements; Kitsu supplies dated anime episodes and manga/manhwa chapters; Wikidata supplies day-precision movie/book releases and documented successors/collection continuations. Duplicate season premieres and sequels are collapsed. Three concurrent workers check every library item, progressively update only Upcoming with checked/total counts, cache successful lookups for six hours using versioned caches, and guard against account changes. Failed or partial lookups retain saved dates and remain retryable; cached episode fallbacks are not marked freshly checked. Discovery never changes watch/read progress or catalog identity. Catalog coverage, especially future chapter dates and books without Wikidata identity, is not guaranteed.

Home summarizes the library, active shows, precise next unwatched episodes, recent dated activity, and provider-dated upcoming releases. Setting a movie to Finished records its first dated watch in Activity; explicit rewatch remains a separate action. Newly added signed-in titles resolve their account library ID before watch history is saved.

The Activity page presents watches and manga/manhwa/book reading progress as a continuous History timeline with day markers, artwork, type filters (including Reading), title links, date editing, and pagination. Reading sessions for the same title and local day combine into one card before pagination, with a highlighted chapter or page start/end range and no synopsis. Each underlying session retains its editable date. Chapter/page increments, committed input edits, and finishing save an endpoint plus the first newly read position; known totals clamp progress. Legacy endpoint-only events remain supported without inventing earlier reading dates. Existing reading progress without events appears as Earlier with no fabricated read date. Reading events do not count toward viewing-time statistics.

History tries a custom banner, verified title-matched artwork, an original episode still, a title banner, then an original provider cover or saved cover. It prefers native images at least 1280px wide and 600px tall with aspect ratios between 1.3 and 2.4. Landscape cards follow the source proportions, filling both dimensions without zoom-cropping ordinary artwork. A portrait-only fallback has a large 44%-width cover with title/context beside it, rather than a tiny poster inside a panorama. Ultra-wide fallback images retain their full width and proportions with a separate caption below. The full-image button opens the exact source. Genuine verified art covers Guns Akimbo, The Mentalist S2 E2, F1 (including the short title), 300 (2006/2007), and Zodiac; actual dimensions are in the provenance file. 300 now uses a 1920×1080 still rather than the old 4:1 header strip. New Kitsu results retain original landscape and cover URLs. Sources remain genuine, with no artificial 4K upscaling or promise that every provider has 4K art.

The season explorer in series/anime details supports individual watched/undo/rewatch actions and a confirmed, idempotent whole-season action. For provider-dated guides, only released episodes can be marked watched; count-only anime without verified dates remain individually trackable but do not expose whole-season actions. Optional backdating is available when logging a watch, and Activity allows date corrections. Calendar presents a desktop month and mobile agenda from followed-title episode dates plus watched days. Stats shows event-based watch time, movie/episode counts, trends, active days, top titles, genres, actor/director rankings linked to existing person details, and a yearly activity map. Unknown runtimes are excluded from watch-time totals and disclosed.

New destinations share the existing shell and use hash routes so the local file still works. Library/Explore remain the existing personal/catalog surfaces, and Pick 4 Me remains its existing decision workspace. A newly empty library gets discovery and Pick 4 Me entry points rather than zero-filled dashboard cards.

Legacy title status and scalar progress are preserved as an undated baseline; they do not create fabricated WatchEvents or historical Stats. Authenticated watch events and explicit episode progress are owner-scoped in Supabase. Guest activity remains in the guest browser key.

For authenticated users, My List and every status, rating, favorite, progress marker, note, history-derived preference, and My List recommendation source belong only to the active Supabase account. Catalog facts remain shared. Account changes clear the prior private state before loading the next account, so a new account sees a loading state followed by its own library or a deliberate empty state—never another account's titles. Guest browser data remains separate and is not automatically imported after sign-in.

## Search and People

The primary search has a persistent two-option Library / Online segmented switch inside the input. Both choices stay visible on a neutral surface; the selected choice uses the theme's contrasting foreground/background colors, with cobalt keyboard focus. Library is the default and searches only saved titles and their people, without public search requests; an empty result offers Online search with the same query. Online searches public title/person providers and connects to the All titles destination. Explicit media tabs restore Library scope. Switching sources keeps the query, invalidates pending public requests, and isolates online errors from local results. Selecting the current source does not restart search. Mobile keeps a single-line navbar with compact localized Lib/Web labels; desktop shows full source labels with icons. Labels, hints and source actions support English, French and Arabic.

Autocomplete retains normalized token-prefix and typo-tolerant matching. Exact title/alternate-title matches precede franchise films or partial matches; then available audience counts, popularity ranks, provider weights or sitelink counts determine popularity, with relevance/name breaking ties before the five-person/six-title limits. Search position, Wikipedia article length, and ratings averages are not audience-popularity measurements; missing metrics remain unknown rather than fabricating a score. Full result surfaces retain relevance-first ordering. People and Titles are grouped by inferred query intent.

Public search deduplication uses provider identities and compatible media type, year and alternate titles, including diacritics and common Japanese long-vowel romanizations. Provider aliases are retained so a Kitsu/TVMaze duplicate still links to the correct saved item. Animated Kitsu films belong to Movies, not the episodic Anime category; anime-only enrichment/recommendation lookups exclude those films. Different provider IDs within one catalog, release years, media adaptations, numbered book volumes and anime specials remain separate when equivalence is unproven. Search never deletes library entries or changes their private progress.

People results use stable 4:5 portrait cards with bounded widths, face-biased cropping, and initials fallbacks for absent, broken, or unusably small art. Their loading skeletons use the same geometry.

Opening a person always performs direct profile resolution and credit lookup when the cache is cold. The page shows a natural-width portrait, available factual chips, exact age or age at death, a collapsed biography when long, and one popularity-ranked Known For shelf. Known For resolves missing or unsuitable raw credit art through the title's stable Wikidata/Wikipedia identity and uses HTTPS artwork, retaining a fixed fallback only when no image exists. Additional role-grouped credits are progressive disclosure under Full filmography; the default view does not repeat Acting/Directed/Written variants of the same work. Person/title navigation participates in browser history and returns to the prior state.

## Pick 4 me

Pick 4 me is a temporary decision workspace rather than a permanent preference profiler. It has a desktop split screen: the left keeps the chosen recommendation, its facts, explanation, actions, optional list strip, and session history visible; the right holds the conversational interaction and compact controls. On mobile, accessible Chat and Pick tabs expose one workspace at a time.

### Supported requests

The assistant supports direct requests and conversational discovery, including random words, multiple concepts, moods, natural language, guided follow-up questions, suggested-answer chips, individual recommendations, and natural lists such as three/five/ten picks. Sources are explicit:

- **Mix:** relevant saved and discovery candidates.
- **My List:** saved library candidates only; no silent broaden to catalog results.
- **Discover:** external catalog candidates grounded in provider data.

Users can choose exact media formats, ask for one or a list, change or remove semantic context chips, regenerate, reject, save, open details, and restore a result through either transcript links or session history.

### Pick and Surprise modes

- **Pick 4 me:** full conversation, direct requests plus no more than three useful guided questions, chips, source/type/output controls, result and history.
- **Surprise me:** shares the workspace and source/format controls but intentionally has no free-text composer. It offers a safe/unusual tuning choice and a regenerate action.

Fresh Pick defaults are Mix, All formats, and one result. Closing the workspace ends the temporary session. Reopening begins fresh. Switching modes clears destination content and scroll position but preserves source and format. Start over resets only the current mode and its history, returns that mode to Mix, and remains in the current mode. Details is special: explicit Back and browser Back restore the exact picker transcript, selected result, controls, mode, unsent draft, and relevant scroll positions.

Reading cursor corrections also correct History: lowering a chapter/page trims any overlapping logged range and removes sessions entirely beyond the corrected position, without creating another read event. This happens atomically in the owner-scoped RPC and mirrors locally for guests. Daily reading cards use compact, vertically centered layouts with an intrinsic-ratio cover column flush to the outer edge. All History cards omit synopsis text. Movies prefer genuine HD landscape artwork, with verified replacements for The Machinist and Man of Steel in addition to the existing curated titles. No source is upscaled or fabricated; other movies still depend on available provider artwork.

## Recommendation-quality requirements

The system must retain the entire request rather than independently matching the first recognizable word.

- **American animation:** must respect both American origin and animation; animation is near-hard when factual candidates exist and origin is strongly weighted.
- **Family movie suitable for kids:** must retain movie format, family context, and known child-safety constraints. Unknown classifications are not blanket-safe.
- **Johnny Depp medieval movie:** must consider the named person and medieval context; broad lexical matching must not confuse `deep` with `Depp`.
- **Moroccan deep drama:** must preserve combined origin/culture, tone/semantic trait, and drama intent. `Moroccan` and `medieval` can legitimately trigger one useful clarification when meaning is ambiguous.
- **Guns:** needs factual firearms, shootout, armed-conflict, or weapon evidence; generic action must not pad a gun-recommendation list.

Type, explicit exclusions, named people/titles, requested animation, source, and known child safety are hard or near-hard constraints. Genre, theme, origin, era, setting, and strong mood are high-weight evidence. Runtime/pages and broad adjectives are softer and should surface a visible tradeoff when imperfect. Recommendations exclude shown/rejected IDs across the session, sample without replacement from the strongest relevant shortlist, and apply a small diversity penalty. When a meaningful pool is exhausted, the UI should prefer a shorter relevant list over unrelated padding.

## Current implementation versus intent

The current code and tests implement structured local parsing/scoring, phrase-aware multi-concept handling, source isolation, intent accumulation and explicit direction reset, context-preserving details return, weighted variation, history exclusion, and explicit local fallback when hosted AI fails. AI can interpret/rank a limited factual shortlist but is optional and requires sign-in/hosted configuration.

The repository does not establish that live model quality has been evaluated in production. Cross-session recommendation history, advanced behavioral learning, collaborative picks, a durable global rate limit, real model-quality evaluation, and broad localization of new static recommendation controls remain deferred or unsupported.
