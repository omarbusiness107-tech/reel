## Authority and scope

The native app exists in `mobile/`; it is not a WebView and this is not a Kotlin migration. Root `reel.html` remains a separate functional website. NotebookLM was queried using `03cc1bfa-6547-4f80-96b4-be709357a773`; its response incorrectly described native mobile as absent and used legacy storage context. Current native files and current `docs/project-memory/{ARCHITECTURE,CODE_MAP}.md` override those stale statements. Do not propagate the stale answer into implementation.

The user brief describes movie/TV discovery but existing libraries include anime, books, manga and manhwa. Preserve all saved records and website capabilities. Native chapter/page tracking is explicitly out of current native scope; its absence is not permission to delete reading data or hide it from the native Library.

Legend: **N** = native implementation present; **P** = partial/limited native support; **W** = website/shared capability, not equivalent native UI; **O** = optional proposal; **U** = unsupported in inspected native code. Source paths below are existing unless explicitly marked proposed. `mobile/` paths are abbreviated `m/` only in this matrix.

## Explicit native parity limits

1. Website Pick 4 me has separate Surprise mode, source Discover, multiple media types, 3/5/10 lists, historical result selection and rejection/seen actions. Native UI currently has one merged Ask, Mix/My library, Any watch/Films/TV/Anime, one/three results. Shared engine support is not proof of native controls. Core redesign preserves native controls; full web parity is **optional O-04**, not an accidental requirement hidden in restyling.
2. “Guide Me” is a product concept fulfilled by native follow-up questions, not a current separate native route. Proposed entry explicitly begins that existing flow. It must not split conversation state.
3. Native New chat currently retains source/format. Website Start over resets Mix. Keep this distinction unless a separately documented product change is requested. Fresh native conversation still starts Mix.
4. Native detailed scroll restoration is mostly a consequence of mounted routes/queries, not a fully implemented explicit snapshot system. Rotation can remount Library by column count; Ask remounts on changed prompt/account key. Reliable restoration is a bounded redesign behavior improvement, not a claim it already works everywhere.
5. Native public reviews, streaming trailers, provider availability, casting/download, microphone input, games, friends/followers, push/reminders, account deletion and permanent chat history are not implemented. No inactive “coming soon” controls occupy the redesigned primary UI.
6. Native episode guides lack episode synopsis/still fields; calendar does not implement the web's complete multi-provider movie/manga release discovery. Statistics lack the reference's year heatmap, weekday chart, monthly line chart, peak-hour and week-comparison service. Native viewing time is estimated from **known logged runtimes**, not OS screen time.
7. Native reading records remain visible, but chapter/page progress editing and reading events in native Activity are outside implemented viewing-client scope. Web access remains available. No migration of those records is allowed.

## Known risks identified by reading, not runtime failures claimed

- Ask source/format controls can change during a pending request while its prepared state uses older values. Redesigned options must capture a request snapshot and disable changes or cancel explicitly; never relabel old results with new scope.
- Ask automatically scrolls each newest message into view. Redesign should only auto-follow when user is near the end; otherwise show “New response” anchor. This changes presentation behavior and requires tests.
- Ask clears draft before completion and currently has no explicit Cancel button. Preserve a failed/cancelled submitted request for Retry; keep history privacy boundary. New retry/cancel controller is B work.
- Calendar's seven cells and Stats' 14 bars can be narrower than 48 dp. Agenda/accessible inspector solves this; enlarging overlapping hit regions does not.
- Stats builds its 14-day series from range-filtered events; at month boundary previous-month days may be zero under “This month”. Core redesign must label that scope, not silently change aggregation. A future global last-14-days change needs separate tests and copy.
- Profile footer hardcodes 1.0.0 while mobile package reports 1.0.2. Use actual app version in redesign; do not publish an invented version string.
- Recent historical captures are web, not hardware. Device Back, text scale, email link dispatch, SecureStore survival and frame pacing remain acceptance gates.
- Current root `.gitignore`, `package.json`, `package-lock.json` are modified; `tsconfig.json` and `.planning/debug/upcoming-only-one-title.md` are untracked at baseline. These are pre-existing work and must not be reverted or bundled into redesign tasks without deliberate ownership.
